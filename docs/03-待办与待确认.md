## 二、下一步的第一件事：判定用户手上的 lua 属于哪套 AI

用户表示会提供"本地的 rush duel 卡组机器人逻辑 lua"。拿到后按下表判定：

| 判据 | WindBot（C#） | Percy Lua AI |
|---|---|---|
| 扩展名 | `.cs` | `.lua` |
| 是否含 `require("ai.mod.` | 否 | **是**（决定性） |
| 是否含 `AI.SelectCard` / `AI.SelectChain` / `OnSelectIdleCommand` | 否 | **是**（决定性） |
| 是否含 `class XxxExecutor : DefaultExecutor` | **是**（决定性） | 否 |
| 是否含 `[Deck("...", "AI_...")]` | **是** | 否 |
| 是否含 `AddExecutor(ExecutorType.` | **是** | 否 |

### 判定后的分支

- **分支 A：是 Percy Lua AI（`ai/decks/*.lua`）**
  - 说明用户之前对战的"牌组机器人"是客户端内置 Lua AI
  - MDPro3 需要先补 `PercyOCG.StartAI()` 接线（`src/MDPro3/Assets/Scripts/MDPro3/Duel/PercyOCG.cs`）
  - 需要先确认 Percy 的 AI 驱动逻辑在**客户端**还是**核心**里（原版 ygopro 在客户端里驱动 `ai.lua`，
    而 MDPro3 只搬了 `ocgcore.dll`）——**这是分支 A 的最大不确定性，需要进一步验证**
  - 优点：能直接复用用户已有的 Lua AI

- **分支 B：是 WindBot 的牌组 AI**
  - 说明用户记错了语言（WindBot 是 C#）
  - 直接在 `Assets/Scripts/Windbot/Game/AI/Decks/` 下写 RD 执行器
  - 注意：**必须以 MDPro3 内置的那份 API 为准**（比上游旧，见 `02` 第 5.1 节）

- **分支 C：是卡片效果脚本（`c*.lua`）**
  - 那只是卡片逻辑，不是 AI；`ygopro-rush-duel/script/` 里已经有了

## 四、阶段 0 的具体操作清单（链路验证）

前提：一台装有 MDPro3 的 Windows 机器。

1. 找到 MDPro3 的安装根目录（含 `cards.cdb`、`Data/`、`Expansions/` 的那一层）。
2. 在根目录下建/确认 `expansions/` 目录，按下列布局放入 RD 数据：

   ```
   expansions/
   ├── RD Standard.cdb          （来自 src/ygopro-rush-duel/）
   ├── RD Alternate.cdb
   ├── RD Patch.cdb
   ├── lflist.conf
   ├── strings.conf
   └── script/
       ├── special.lua          ← 触发 RD 的关键文件
       ├── RDBase.lua
       ├── RDRule.lua
       ├── RDMaximum.lua
       ├── RDFusion.lua
       ├── RDRitual.lua
       ├── ...（其余 RD*.lua）
       └── c120*.lua 等卡片脚本
   ```

   > 注意大小写：服务器找的是小写 `expansions/`。Windows 不区分大小写，
   > 但 MDPro3 客户端侧的 `Program.PATH_EXPANSIONS = "Expansions/"` 是给客户端 VFS 用的，
   > 两者在 Windows 上会指向同一个目录。

3. 启动 MDPro3 → 单人/人机 → 随便选一个现有 bot 开一局。
4. **预期现象**（证明 RD 生效）：
   - 起始手牌 4 张，抽卡阶段抽到 5 张
   - 主要阶段可以**多次通常召唤**
   - **没有主要阶段 2**
   - 场上怪兽的效果**每回合只能发动 1 次**
   - bot 会乱打（它的 `.ydk` 是 OCG 卡，不在 RD 卡池里）—— 这是**预期内**的
5. 记录结果：
   - 如果规则变了 → 链路打通，进入阶段 1
   - 如果没变 → 检查 `special.lua` 是否真的被读到（可先在 `expansions/script/special.lua`
     里加一行 `Duel.LoadScript("nonexistent_probe.lua")` 制造报错，看游戏内是否弹出脚本错误）
   - 如果普通模式被破坏且不希望如此 → 直接进入阶段 2

## 五、阶段 2 的三种隔离方案（备选）

| 方案 | 做法 | 侵入性 | 需要重编 |
|---|---|---|---|
| (a) 目录切换 | RD 模式启动前把 `special.lua`+`RD*.lua` 拷进 `specials/`，普通模式启动前清掉 | 低 | 仅 C# |
| (b) 启动参数 | 给 `ygoserver` 加一个 mode 参数，控制是否 `preload_script("special.lua")` | 中 | C++ + C# |
| (c) 双数据根 | 维护两套 `Expansions/` 状态，由启动器切换 | 低 | 无 |

`specials/` 目录在 `ScriptReaderEx` 里是**最高优先级**，天然适合做"临时覆盖层"，
所以方案 (a) 最省事。

## 六、风险提醒

1. **MDPro3 内置 WindBot 比上游旧**（见 `02` 第 5.1 节）——写执行器时 API 要对齐内置版。
2. **`special.lua` 全局生效**——装 RD 扩展会让本地人机全部变 RD。
3. **`bot.conf` 是共享资源**——MDPro3 的 README 说它从 YGOMobile 同步而来，
   新增 RD bot 条目时注意别被覆盖。
4. **改 C# 需重编 Unity 工程**——若暂时没有构建环境，只能先做数据层验证。
5. **WindBot 架构局限**（见 `src/windbot/AGENTS.md`）：
   无法预演卡片脚本；`AI.Select*` 是"预先选择"，多段连锁可能错位。
   RD 卡效果相对简单，风险低于 OCG。
